## 1. ภาพรวม

- **แนวเกม:** เลี้ยงและพัฒนาร่าง Servant แล้วต่อสู้เอาตัวรอด แบบผลัดกันเป็นเฟส (ไม่ใช่เรียลไทม์)
- **ผู้เล่น:** 8 Master ต่อแมตช์ ช่องว่างเติมบอท
- **ความยาว:** 24 วัน (ในเกม) ประมาณ 20–30 นาที
- **ชนะ:** Master–Servant คู่สุดท้ายที่รอด หรือมีแต้มสูงสุดเมื่อจบวันที่ 24 ได้ครองจอกศักดิ์สิทธิ์
- **แพลตฟอร์ม:** เบราว์เซอร์ PC และมือถือ (UI แบบแตะ/คลิก เหมือนต้นแบบ)

## 3. ลำดับแมตช์

1. **Lobby** — ทุกคนกด "พร้อม" แล้วนับถอยหลัง ที่ว่างเติมบอทให้ครบ 8
2. **Summoning** — แต่ละคนได้ Servant ร่างเริ่มต้น (สุ่ม 3 ให้เลือก 1 หรือสุ่มตามตั๋วอัญเชิญ)
3. **DAY 1 → 24** — แต่ละวันมีเฟสตามข้อ 4
4. **ประกาศผล** — จัดอันดับ 1–8, แต้มเข้า Ranking ซีซั่น, รางวัล (Bit / Dust / ตั๋ว)

## 5. ต้นไม้ Ascension ⚠️

Servant มี 4 ขั้น แต่ละร่างกำหนด Token ที่ต้องจ่าย (เหมือนตัวเลขใต้รูปใน DigiDex ต้นแบบ) และแตกกิ่งได้

```
ขั้น 0  วิญญาณวีรชน (ร่างเริ่ม)
          │
ขั้น 1  [กำลัง 3] Saber-ร่างเยาว์   [ว่องไว 3] Lancer-ร่างเยาว์   [มานา 3] Caster-ร่างเยาว์ ...
          │
ขั้น 2  [กำลัง 5 ว่องไว 2] Saber        [โคลนดำ 4] Saber Alter
          │
ขั้น 3  [กำลัง 8 มานา 4] Saber ร่างสมบูรณ์ (ปลด NP Lv3)
```

- ร่างที่ใช้ **โคลนดำ** แรงกว่าแต่เสีย HP ทุกวัน (คล้ายร่างพิเศษจาก Poop ในต้นแบบ)
- **Fusion (Jogress):** Servant 2 ตัวที่ขั้น 2 ขึ้นไปรวมเป็นร่างพิเศษได้ ใช้ในโหมด Co-op หรือเมื่อผู้เล่น 2 คนทำสัญญาพันธมิตร ⚠️
- **NP ระดับ:** Lv1 ปลดที่ขั้น 1, Lv2 ขั้น 2, Lv3 ขั้น 3 แต่ละครั้งใช้ต้องมีเกจ NP เต็ม (เติมจากการต่อสู้)

ต้นไม้ทั้งหมดเก็บเป็นข้อมูล (`shared/servants.json`) เพื่อปรับบาลานซ์ได้ง่าย เหมือนหน้า BUFF & NERF ของต้นแบบ

## 6. การต่อสู้ ⚠️

- ค่าสถานะคำนวณจาก Token ที่สะสม + ร่างปัจจุบัน: กำลัง → ดาเมจ, ว่องไว → โจมตีก่อน/หลบ, มานา → ต้านเวท + เติมเกจ NP
- คนที่ตั้งรับลดดาเมจ 50%, คนที่ซ่อนตัวมีโอกาสไม่ถูกเจอ (ตามค่าว่องไว)
- ถ้า 2 คนเลือกโจมตีกันเอง = ปะทะเต็มรูปแบบ 3 รอบ
- **Command Seal 3 ครั้ง** ใช้ได้ในเฟส ③: ฟื้น HP เต็ม / หนีการต่อสู้ / ใช้ NP ทันที
- HP หมด = Servant สลาย Master ตกรอบ ลำดับที่ตกรอบคืออันดับ

## 7. บอท

บอทเลือกการกระทำผ่านช่องทางเดียวกับผู้เล่น (ส่งคำสั่งเข้า server) จึงใช้แทนคนที่หลุดได้ทันที

- **ฝึก:** เลือก Token ที่ขาดสำหรับร่างถัดไปในเป้าหมาย (สุ่มเป้าหมายตอนเริ่ม)
- **Ascension:** เปลี่ยนร่างทันทีที่ Token พอ
- **สงคราม:** โจมตีคนที่ HP ต่ำสุดที่ตัวเองชนะได้ ถ้า HP ตัวเองต่ำกว่า 35% ตั้งรับ/ซ่อน
- **ระดับยาก:** ง่าย = สุ่มบางส่วน, ปกติ = ตามกฎ, ยาก = คำนวณผลการปะทะล่วงหน้า

เพราะเป็นเกมเฟส บอทไม่ต้องมี pathfinding หรือเล็งเป้า ทำง่ายกว่า v0.1 มาก

## 8. สถาปัตยกรรมเครือข่าย

เกมแบบเฟสไม่ต้องใช้ระบบทำนายการเคลื่อนไหว จึงง่ายกว่าแอ็กชันเรียลไทม์มาก

```
Browser (Vite)  ⇄  WebSocket  ⇄  Node.js Game Server
ส่ง "การเลือก" ของเฟส        ถือสถานะเกมทั้งหมด, จับเวลาเฟส, คำนวณผลต่อสู้, รันบอท
แสดง UI + แอนิเมชัน           ส่งสถานะใหม่ให้ทุกคนเมื่อเฟสเปลี่ยน
```

- Server ตัดสินทุกอย่าง client ส่งแค่ตัวเลือก จึงโกงยาก
- ผู้เล่นที่หลุดแล้วกลับมาได้รับสถานะล่าสุดทั้งก้อน (ระหว่างหลุดบอทเล่นแทน)
- ไลบรารี `ws` ฝั่ง server ส่ง JSON
- โครงสร้าง: `client/` (ของเดิม), `server/` (room, phase, bot), `shared/` (ข้อมูล Servant, สูตรต่อสู้)
- ภายหลังถ้าต้องการบัญชีผู้ใช้/อันดับ/ซีซั่น ค่อยเพิ่มฐานข้อมูล

## 9. นอกแมตช์ (ทำทีหลัง)

Ranking + ซีซั่น + Hall of Fame, Throne of Heroes (คอลเลกชัน), กาชาอัญเชิญด้วยตั๋ว (ไม่ใช้เงินจริง), หอคอย 100 ชั้น, ห้องพัก Servant, โหมด Co-op 1–4 คน, โหมดสอนเล่น

## 10. แผนพัฒนา

1. **M1 — แมตช์ออฟไลน์กับบอท 7 ตัว:** 24 วัน, 4 เฟส, Servant 2–3 สาย, ต่อสู้แบบคำนวณ
2. **M2 — ออนไลน์ 8 คน:** server + WebSocket + Lobby กดพร้อม + เติมบอท
3. **M3 — Ascension ครบ + บอสรายวัน + Command Seal + NP 3 ระดับ**
4. **M4 — Servant ครบ 7 คลาสพร้อมกิ่ง Alter, บาลานซ์**
5. **M5 — ระบบนอกแมตช์ (ข้อ 9)**

## 11. ข้อสังเกตลิขสิทธิ์

Fate เป็นของ TYPE-MOON ส่วนต้นแบบเองก็เป็นแฟนเกมไม่หวังกำไร ถ้าทำแบบเดียวกัน (ฟรี ไม่ขายของในเกม) ความเสี่ยงต่ำ แต่ถ้าจะหารายได้ควรออกแบบตัวละครเอง
